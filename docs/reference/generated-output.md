# Generated output and the URL scheme

Everything under `www/` except the hand-written shell and `badges/` is generated from `kb/`. The rule
is absolute: **edit the source, never the output.** A hand-edit of a generated file is overwritten by
the next build and never reaches the site.

## Source versus output

| Path | Kind | Owner |
|---|---|---|
| `kb/databricks/<id>.yaml` | **source**, tracked | you |
| `kb/posts/<slug>/index.md` | **source**, tracked | you |
| `kb/posts/<slug>/images/` | **source**, tracked | you (the builder copies it) |
| `kb/posts/<slug>/materials/` | **source**, tracked, never deployed | you |
| `www/index.html` | **source**, tracked | you - the app shell |
| `www/app.js`, `www/styles.css` | **source**, tracked | you |
| `www/assets/`, `www/robots.txt`, `www/CNAME`, `www/site.webmanifest` | **source**, tracked | you |
| `www/disclaimer/`, `www/subscribe/` | **source**, tracked - static pages no generator owns | you |
| `www/badges/` | **output, but tracked** | `build_badges.py` |
| `www/databricks.features.json` | output, gitignored | `build_features.py` |
| `www/learn/`, `www/posts.json` | output, gitignored | `build_posts.py` |
| `www/databricks/` | output, gitignored | `build_entries.py` |
| `www/sitemap.xml`, `www/feed.xml` | output, gitignored | `build_entries.py` |
| `reference/` | output, gitignored | `fetch_reference.py` |

**`www/badges/` is the deliberate exception.** Rendering its `og.png` files needs a Chromium-based
browser, which CI does not have, so the generated pages are committed instead. Everything else is
rebuilt on every deploy.

## What deploys

The Pages workflow uploads **`www/` and nothing else**. `kb/`, `scripts/`, `agents/`, `docs/`,
`reference/`, and the repo Markdown files are never published. This is why `www/` must be the web
root when you preview locally: `python -m http.server 8777 -d www`.

## The published URL scheme

Base: `https://rebricked.org`

| URL | What it is | Generated by |
|---|---|---|
| `/` | The app shell. Everything on it renders client-side from the JSON | hand-written |
| `/#<entry-id>` | Deep link opening a single entry in the app | `app.js` routing |
| `/?q=<term>` | Deep link reflecting the search box | `app.js` routing |
| `/?quiz=<score>` | The "beat this score" challenge banner | `app.js` routing |
| `/databricks/` | Vendor hub: every entry grouped by category | `build_entries.py` |
| `/databricks/<id>/` | One crawlable page per entry, with unique title, description, canonical, OG, and JSON-LD | `build_entries.py` |
| `/learn/` | Guides index | `build_posts.py` |
| `/learn/<slug>/` | One guide | `build_posts.py` |
| `/badges/<n>-of-5/` | Quiz-result share page, with an absolute `og:image` | `build_badges.py` |
| `/sitemap.xml` | Every entry page and guide | `build_entries.py` |
| `/feed.xml` | RSS 2.0, newest tracked change first, one `[Guide]` item per post | `build_entries.py` |
| `/disclaimer/`, `/subscribe/` | Static pages | hand-written |

**The `/{vendor}/` segment is deliberate future-proofing.** Today everything is `databricks`, but an
entry may carry a `vendor` field and a new vendor slots in as a new top-level namespace
(`/snowflake/...`) with no structural change.

The two page families answer different needs: the app is the interactive experience, and
`/{vendor}/{id}/` exists because a client-rendered SPA is an empty shell to a crawler and its `#id`
deep links are not distinct documents. See
[explanation/the-seo-layer.md](../explanation/the-seo-layer.md).

## Regenerating everything

```bash
python scripts/build_features.py \
  && python scripts/build_posts.py \
  && python scripts/build_entries.py
# and, only if you changed them and have Edge/Chrome:
python scripts/build_badges.py
```

## Checking that output is stale

```bash
python scripts/build_features.py --check
```

Fails if the built JSON on disk does not match `kb/`. Useful in a pre-commit hook or when you are
unsure whether what you are previewing is current.

## Before you commit

```bash
git status --short
```

Should show only `kb/**`, `www/app.js` if you edited `NAV`, `docs/**` if behaviour changed, and
`CHANGELOG.md`. If a generated path appears, either it is `www/badges/` (fine, that one is tracked)
or something has fallen out of `.gitignore`.
