# Get the site running

You will install the single dependency, build the data the page fetches, serve the site
locally, and confirm the schema gates pass. At the end you will have the Databricks-style
console running on `localhost` with all 100-plus entries in it.

**You need:** Python 3.9 or newer, and a browser. No Node, no framework, no account.

## 1. Install the one dependency

```bash
pip install pyyaml
```

That is the whole toolchain. PyYAML is a dependency of the *build scripts* only - the site
itself ships as plain HTML, CSS, and one vanilla-JS file. See
[explanation/architecture.md](../explanation/architecture.md) for why it stays that way.

## 2. Build the data

The entries live as one YAML file per entry in `kb/databricks/`. The page fetches a single
JSON array, which is **build output** and is not in git:

```bash
python scripts/build_features.py
```

You should see it report the number of entries written to
`www/databricks.features.json`. Open that file if you like - just do not edit it. The next
build overwrites it, so your change would never reach the site.

## 3. Build the guides

```bash
python scripts/build_posts.py
```

This renders `kb/posts/<slug>/index.md` into `www/learn/`, copies each post's figures, and
writes `www/posts.json`. It runs *after* `build_features.py` because it resolves
`{{entry:<id>}}` shortcodes against the data you just built.

## 4. Check both gates pass

```bash
python scripts/validate.py
python scripts/validate_posts.py
```

Both should print `OK`. If either does not, you have a stale build - re-run steps 2 and 3.
These are the same two commands CI runs on every pull request.

## 5. Serve it

The page fetches JSON, and browsers block that over `file://`, so you need a real HTTP
server. Serve `www/` as the **web root** - that mirrors exactly what GitHub Pages publishes:

```bash
python -m http.server 8777 -d www
```

Open <http://localhost:8777/>.

## 6. Look around

Confirm each of these works, because each one is a contract you can break later:

- **Search** for `Delta Live Tables`. You should get the renamed card, pointing at Lakeflow
  Declarative Pipelines.
- **Click a rail section** (say *Jobs & Pipelines*). The list filters to that section's
  entries. Sections with no entries show an honest empty state, not a blank page.
- **Untick "Active"** in the status filter. Everything currently in use disappears, leaving
  superseded names and deprecations.
- **Click a bar** in the year timeline. It filters to that year.
- **Open <http://localhost:8777/learn/>**. The guides index, built in step 3.
- **Open <http://localhost:8777/databricks/>** - and note that it 404s. The crawlable entry
  pages are generated by a script you have not run yet. Run
  `python scripts/build_entries.py` and reload.

## What you built

```
kb/databricks/*.yaml  --build_features.py-->  www/databricks.features.json  --fetched by--> www/app.js
kb/posts/<slug>/      --build_posts.py----->  www/learn/, www/posts.json
        (both)        --build_entries.py--->  www/databricks/, sitemap.xml, feed.xml
```

Everything on the right of an arrow is generated and gitignored. Everything on the left is
source, and is the only thing you ever edit or commit.
